# P2.1 分类选题：实施与验收

日期：2026-11-14（Asia/Shanghai）。本轮授权是用户要求将已讨论的资讯分类加入系统。沿用本地、半自动与现有Plus手动审稿方式，不要求模型API。

## 完成内容

- 六种资讯主类与“待分类”：模型技术、产品功能、开发者智能体、行业应用、商业生态、工作社会影响。
- 独立的开放情况、材料证据类型、可多选内容栏目与制作进度标签。
- 新闻与选题卡片标签、组合筛选、选题类别统计入口、逐字段人工更正与备注。
- 人工修改跨刷新/采集/初筛/重启保留。恢复自动时只重置指定分类字段；UI保留人工进度和备注。
- 导出保留分类、规则/人工来源、栏目、备注、原始出处和待核实项；支持当前分类过滤条件。
- 默认规则分类不调用模型；不自动标记本人实测或已发布。制作进度只是本地标记，不触发任何发布行为。
- 新增editorial_taxonomy表，schema3→4前SQLite备份，新闻、选题决定、模型历史保留。
- 新增安全代码升级脚本upgrade_p2_1.ps1，识别已交付的旧版本摘要，保留.env、data、logs、用户文件及原n8n卷。

## 实测

- 125项自动化测试通过，1条上游Starlette/httpx弃用提示，无跳过。包括既有回归、9个当前选题类别样例、新模型分类、未知/预告/否定开放措辞、人工覆盖与恢复、组合筛选、导出、非法输入、新闻/事件标签独立、schema3备份与选题/模型缓存保留，以及PowerShell升级保护。证据：evidence-p2-1/pytest.txt。
- 浏览器：桌面与390px手机无横向溢出；类别入口、两种页面标签、编辑、刷新保留、栏目多选、组合过滤、带标签导出、恢复自动保留人工进度/备注、备注纯文本显示均通过；JS错误0，模型请求0。证据：browser-qa.json与两张截图。
- 实际使用旧RSS数据快照：240条历史新闻均得到分类，239条在近期候选窗口；不代表本轮重新采集实时消息。数据与人工测试笔记不预装到交付包。
- 完整P2 ZIP升级演练（PowerShell7/Linux）：原.env字节、240条新闻、模拟的9个已选题、模型缓存、用户自建表与笔记保留；文件升级不改数据库，启动后schema4就绪，迁移前schema3备份可读取。证据：upgrade-proof.json。
- Ruff检查、格式检查、三个JS语法检查通过。原生API实际启动并验证ready及分类接口；docker compose config --quiet通过。本轮未构建/运行P2.1 Docker镜像，未在云端重新运行n8n。
- 工程ZIP另目录解压回归结果见package-pytest.txt；文件清单摘要和下载文件哈希单独核对。

## 本机待验

用户Windows升级并构建启动P2.1；确认原9个选题仍在、分类可筛选和修改、下一轮n8n采集继续运行。现有工作流接口和数据卷配置未改变，不需要重新导入工作流。真实模型调用和飞书写入不在本轮验收范围，仍保持可选。

## 边界

自动分类依据主条目标题、RSS摘要与路径线索，不是全文语义模型，可能误判。开放状态只代表原始摘要中的线索，不保证当前账号/地区可用。证据类型不是核查结论，内容栏目是制作计划。

类别统计针对近期全部候选，列表还受推荐/已选题等状态条件影响。选题与原始新闻标签独立，防止一篇新闻的人工实测标记自动传播到合并事件。制作进度与选题决定分别管理。当前分类不改变评分或模型缓存；不生成完整稿件，不自动上传给Plus，不自动发布。
