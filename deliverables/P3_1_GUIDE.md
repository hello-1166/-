# P3.1：面向内容创作者的规则推荐

本版优化“规则推荐”，保留 P3 内容策划台、既有新闻、人工选题和制作记录。仍不调用模型 API，不预测播放量，不将规则匹配当作事实核查。

## 改了什么

1. 不再仅凭 model、code、work 等宽泛词就给高受众分。优先查找创作、办公、购物等具体任务线索。
2. 把“发布日期”“价格/获取方式变化”“对比/效果变化”“新增能力”“演示或操作材料”分开记录。命中关键词只说明有这类线索。
3. 摘要缺失、过短、重复标题或缺少有效原始链接，不自动推荐；原记录保留，可在全部候选中阅读和人工选入。
4. 传闻或未经证实线索不自动推荐。有限开放降低优先级，并提示核对地区、费用、候补等条件；规则无法凭空识别摘要没写出的限制。
5. 保留研究观察，对培训活动和专业医疗场景单独处理，避免误当成大众即用新产品。
6. 推荐默认同一内容方向最多 3 项，每轮最多 10 项。不为凑满数量降低门槛；已选题和已忽略不占待选推荐名额。
7. 每条卡片显示内容方向、推荐或未推荐原因、命中的具体词和针对该方向的建议角度。选题导出也保留这些说明。

内容方向用于推荐编排，不替代原有资讯类别、内容栏目或人工分类。

保持 Docker Desktop 运行。将新 ZIP 解压到独立目录，在能看到 `scripts` 的位置打开 PowerShell。逐条运行：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

```powershell

```

看到 `P3.1 code installed` 后切回原项目，再启动：

```powershell

```

```powershell

```

打开 <http://localhost:8000/topics>，使用 Ctrl+F5 刷新，点“重新初筛”。启动也会重算规则分。现有已选题、忽略决定、分类人工更正和策划快照不被新评分清除。数据库结构仍为版本 5，无需新增表。

升级先校验已知版本，再备份替换的代码；保留 `.env`、`data`、`logs`、自定义文件和 n8n 卷。发现未知本地代码修改会停止，不自动覆盖。不要删除容器卷。

## 推荐为空怎么办

可能已把推荐全部加入选题，也可能候选未满足时间、材料、分数或方向配额。切换“全部候选”查看每条的说明。已选题仍可直接进入 `/plans` 创建内容策划，不必恢复为待选再操作。

新规则会让一些“标题很热闹、材料不足”的消息退出自动推荐，这是保留核实空间，不是删除新闻。手动加入选题不表示系统完成了核实。

## 可调整的配置

默认评分为 100 分制：时效性 20、受众相关 25、变化线索 20、演示潜力 15、来源可追溯 10、材料完整度 10。使用门槛和未证实线索另作调整。分数是规则估计，不同版本不应当作可直接比较的客观质量。

`config/editorial_ranking.yaml` 管理关键词、维度上限、材料要求和同方向配额；`config/selection.yaml` 管理推荐门槛、总数量与回看天数。默认门槛 65。建议先观察实际候选，不必为了出现更多推荐降低门槛。权重总和必须为 100，错误配置会使启动检查停止。

规则只读取已有标题和摘要，不会自动翻译、读取完整原文、学习博主视频或计算真实传播热度。重要研究或新词可能漏选，需保留人工查看入口。继续使用现有 Plus 对导出材料做第二轮编辑判断。
